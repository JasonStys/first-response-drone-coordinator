# Primary research and implementation consequences

By Jason Stys. Checked 2026-10-21. The project is original, generalized and unaffiliated; it does not claim endorsement or operational certification.

- [FAA emergency situations](https://www.faa.gov/uas/advanced_operations/emergency_situations): some first-response operations may qualify for expedited Special Governmental Interest review. An emergency does not automatically authorize noncompliant flying. Consequently, this app has no automatic exception or launch capability and its manual authorization flag is not an official approval.
- [FAA Part 107 waivers](https://www.faa.gov/uas/commercial_operators/part_107_waivers): operational waivers and airspace authorization are distinct concerns. A nominal resource allocation cannot establish regulatory compliance. This repo deliberately does not calculate clearance, legal flight permission or real aircraft trajectories.
- [SQLite transactions](https://www.sqlite.org/lang_transaction.html): multiple readers but a single writer support the selected local architecture. `BEGIN IMMEDIATE` plus revision checks prevents stale concurrent scenario writes and stale proposal persistence. Rollback occurs on closed unsuccessful transactions.
- [Python 3.14 sqlite3](https://docs.python.org/3.14/library/sqlite3.html): parameter binding and explicit connection lifecycle guide database access; SQL fragments never come from uploaded scenarios. Trusted database paths are CLI inputs, not HTTP parameters.
- [FastAPI middleware](https://fastapi.tiangolo.com/advanced/middleware/): centralized request/response handling applies origin, Host, payload and response-header controls. The actual pinned Starlette/FastAPI combination is integration tested for buffered and streamed requests.
- [OWASP session management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html): opaque unpredictable sessions, expiration and restrictive cookies inform the account boundary. Per-session CSRF, server-side roles and local-only provisioning avoid trusting UI state.
- [OWASP drone security](https://cheatsheetseries.owasp.org/cheatsheets/Drone_Security_Cheat_Sheet.html): access control, data protection and communication risks motivate explicitly excluding hardware/radio paths, retaining synthetic data and recording human-reviewed state changes. These design choices are not a drone security certification.
- [Playwright web-server integration](https://playwright.dev/docs/test-webserver): browser acceptance launches an actual disposable FastAPI service with the compiled UI, refusing to reuse another process. Chromium, Firefox and WebKit exercise real cookie/API flows; no route mocks substitute for service success.
- [GitHub Actions secure use](https://docs.github.com/en/actions/reference/security/secure-use): minimal token permissions and full Action commit hashes reduce workflow exposure. No deployment secrets, Actions artifacts or cache uploads are needed here; CodeQL security-and-quality results remain on GitHub.
- [npm audit](https://docs.npmjs.com/cli/v11/commands/npm-audit/) and [network configuration](https://docs.npmjs.com/cli/v11/using-npm/config/): advisory requests use the configured registry; severity controls determine failure thresholds, and default fetch timeouts can be five minutes. The helper preserves the high/critical gate, explicitly includes every dependency type from the lockfile and limits transient-error retries. A provider outage is not a vulnerability result or a clean scan.

## Code quality choices

Self-documenting names such as `authorization_recorded`, `reserve_percent`, `review_state` and `check_revision` describe intent without arbitrary language tricks. Units are explicit; integer percentage-minutes avoid float threshold drift. Headers link generated AST source navigation instead of hand-maintained line numbers. Function/class documentation explains responsibilities and parameters, while comments explain nonobvious boundaries such as authoritative checkbox acknowledgement and immutable revision checks.

The small optimizer deliberately prioritizes correctness/explainability over distributed scalability. Big-O accounts for candidate feasibility checks at each visited state, not just successful recursion. Test coverage percentages name their exact denominator. Versions are pinned for reproducibility, not asserted to be globally newest. A framework's deprecation warning is recorded separately from test outcomes; dependencies must be re-audited on updates.
